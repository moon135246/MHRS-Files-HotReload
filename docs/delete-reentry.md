# 删除松散文件后重新进入

2026-11-14，Steam 版崛起 16.0.2.0，REFramework v1.5.9.1+472-c4b13148。LooseFileLoader 已启用，Debug 中的 Enable file cache 已关闭。游戏重启后需重新检查此开关。此前的冷路径覆盖实验把原内容写回后才删除样本，此页记录实际删除文件后的结果。

## 村内穿戴 279

在进程 4312 中，先穿戴公会十字（279），核对 13 份 Mod 文件的 SHA-256 并删除。用道具箱的“设置外观装备 → 变更外观装备”把手甲换为染花【袖子】（265），确认并退出菜单。探针读到 `f_arm265` 后再次打开道具箱换回公会十字腕甲。然后把 13 份文件放回，等监听器报告恢复，再重复相同的手甲切换。两次切换均在村内实际角色上取样。整个过程未替换个人组合，也没有切换武器。

| 实机读数 | 开始时穿着 Mod | 删除后切回 | 放回文件后切回 |
| --- | --- | --- | --- |
| 手甲 MDF | 6 个 Meira 槽 | Arm、Hand | 原 6 槽，逐槽名称、贴图与启用状态一致 |
| 手甲 Mesh 就绪 / LOD 数 | 是 / 1 | 是 / 5 | 是 / 1 |
| 手甲 Chain 组数 | 15 | 2 | 15 |
| 头盔 USER 的 FullBody | true | false | true |

同一进程中完成了两组删除、放回和换装往返。其中一组用于复测大小写修正。每组往返期间，游戏、Lua 脚本和监听器持续运行。两次早期会话曾在看到原版后退出，同期还有脚本或其他探针操作，未取得可归因的崩溃记录。测试结束时 13 份 Mod 文件均与备份 SHA-256 一致。

| MESH / MDF2 | 见 279 实穿记录 |

资源文件名可能全小写，PFB 内的原始引用可能是混合大小写。ItemTake 实测中仅用全小写文件名清缓存会漏掉碰撞资源。监听器现在从松散引用和场景中的持有者取回引擎使用的拼写。

包内有原件的资源可以按原路径回退。279 的 `f_shadow.mesh` 在本次删除时未命中缓存，也没有找到包内同名原件。单靠这个样本不能证明游戏可重新创建已经删除的 Mod 专属资源。

本机逐项回执、哈希和读数位于 `local-tests/delete-reentry/`，汇总为 `results.json`。

### 多个 MDF 共用透明模板

上次退出前的两步替换分别存在布局冲突。手甲原槽仍声明 `HairCapMaskMap`，改指的 `PL_Default` 没有该槽。身体原槽提供 160 字节参数缓冲区，写到 `PL_Default` 路径的 `Moon_Translucent` 需要 304 字节。用这两组文件离线运行监听逻辑，都在发起游戏加载之前被拒绝。上次退出没有对应的崩溃栈。

在村庄加工店外，将头盔的完整透明材质槽复制到手甲，保留手甲原槽名。两个部件引用 `Moon_Translucent_Dissolve`。修改模板中三个光栅化状态的正面绕序，独立解析确认材质接口相同，再覆盖并恢复模板。每一步都从两个活动 MDF 的实际材质槽读出相同的新 MMTR 地址。第二个 MDF 缺席，以及两个 MDF 就绪后取消提交时，两件装备都保留原 MDF 和原 MMTR。三件装备共用 `Moon_General_Dissolve` 也完成了绑定。

删除单文件 `PL_Default` 覆盖后，身体槽重新绑定到包内模板。测试结束时用 SHA-256 核对了 279 套装的 13 个原文件。透明模板的对照读数见本机 `mmtr-transparent-variant.json`，包内回退见 `mmtr-packaged-group-readback.json`。

此轮试验通过活动 Mesh、松散文件和与游戏版本匹配的 `--baseline-root` 读取 MDF。后续版本已附带原版模板的材质接口，可以用默认监听命令处理有匹配接口的包内 MDF。日志会写明布局不符的材质槽与字段。被拒绝的覆盖文件仍在磁盘上，进入新场景前应修正或移除，游戏自身的资源加载仍会读取它。[当前版本的实测范围](reentry-18.md)
